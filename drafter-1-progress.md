- Design (from `suffix_drafter.hpp`): every trigram of the history (prompt + accepted output) maps to its WAYS most recent end positions in a fixed-size open-addressing table (two slots per nominal token, 48 bytes/slot, appends O(1)). Trigram key deliberately selective — a bigram key fell from 95% to 63% fire rate on a 710k-token corpus, so order 2 is not indexed.
- One trigram key serves all match orders 3..max_match: a proposal reads the slot for the trigram ending at the current token and extends each candidate backwards; matches below min_match propose nothing.
- Voting, not recency: among candidates reaching the longest match, each votes for its continuation; most-voted wins; ties broken by recency. A count never outvotes a longer match. Matches TandemLLM's ngram drafter counting half (0xBakeer/TandemLLM, AGPL-3.0, per NOTICE lines 38-47).
